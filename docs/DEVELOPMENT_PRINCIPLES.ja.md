# 開発・使いやすさの基本方針

[English](DEVELOPMENT_PRINCIPLES.en.md) · [利用ガイド](../README.md) · [リリース手順](RELEASING.md)

**少ない操作で目的に進め、必要なときだけ詳しくできること。** 実装・レビュー・文書更新で共通して使う方針です。現在の CLI と将来画面を追加する場合の両方に適用します。目標として記載しただけで、実装・公開済みとは扱いません。

## 1. 日本語と英語をどちらも正式に扱う

- 初回案内、ヘルプ、質問、確認、状態、エラー、次の操作まで、日本語と英語を同じ範囲で対応する
- 基本はロケール自動判定とし、コマンドの前後で `--lang ja|en|auto` を明示できるようにする。正確な優先順と安全なフォールバックは[利用ガイド](../README.md#表示言語)に記載し、テストする
- コマンド名・オプション名、確認入力、保存済み設定、機械向け形式は言語で変えない。アドレス、パス、鍵、識別子、利用者が入力した値を翻訳しない
- upstream の `hbbs` / `hbbr` のログや OS の診断情報は維持する。補助 CLI の説明を翻訳しても、元の診断を隠したり原因を推測で断定したりしない
- 狭い端末でも読める出力にする。次のコマンドの説明を色・ブラウザー・グラフィカルな画面だけに依存させない

## 2. 簡単さと柔軟さを両立する

- インストール → セットアップ → クライアント設定を先に示す。通常利用でリポジトリの clone、コンパイル、JSON の編集、launchd の内部知識を要求しない
- 検出した LAN と接続済み Tailscale のアドレスは候補として示し、クライアントからの到達確認済みとは扱わない。手入力とアドレスの明示指定も残す
- 必須入力は目的に必要な分だけにし、通常操作、詳細設定、診断の順に見せる
- 適用前にアドレス、保存先、権限、ログイン時の動作、再起動、全インターフェースでの待受けを示す。確認前に取り消した場合は、サービスや設定を変更しない
- セットアップの繰り返しでは既存の鍵とデータを保つ。重要なアドレス・保存先変更は明示し、危険な移行は拒否する。変わらない情報の承認を無用に繰り返させない
- 入力間違いは可能ならその質問で直せるようにする。取消・再試行・安全な状態へ戻す手段を明確にし、編集や戻る操作が未実装・未検証なら利用できると説明しない

## 3. 状態と次の行動を明確にする

- 稼働中のサービス、クライアントに案内する ID／リレーアドレス、公開鍵、保存先、ログイン時の動作を示し、秘密鍵を表示しない
- 設定保存、ローカルプロセスの状態、待受け確認、実クライアント間の接続成功を区別する。ローカルの状態確認だけでエンドツーエンド検証済みにしない
- エラーには分かっていることと具体的な次の一手を添える。一部失敗や復旧失敗を成功として表示しない
- 必要に応じて次の操作案内にも明示した言語を引き継ぐ。コマンド例は安全にコピーでき、置き換える箇所が分かるようにする
- 将来画面を追加する場合は、情報の優先順、操作の位置、戻る導線、狭い画面、コントラスト、文字サイズを確認する

## 4. 文書は結論と短い手順から

- 冒頭付近で、できること、対応する公開済みの版、未リリースのソース変更、未確認の範囲を区別する
- まず最短の通常手順を示す。詳しい条件、詳細設定、例外は後ろへ置く
- 日英のガイドを同じ内容に保ち、用語を統一して、リンクとコマンド例も検査する
- 実装、模擬試験、対象 OS の自動試験、配布確認、実クライアントでの確認を分ける。未実施の確認を成功と記載しない
- 方針を重複して固定せず、この文書を参照する

## 変更時の確認表

- [ ] 日英のヘルプ、初回の質問、確認、状態、エラー、次の操作を確認した
- [ ] ロケールの優先順、日本語の表記揺れ、英語・未知の値・`C`・`POSIX`、空・未設定、macOS の優先言語と取得失敗、コマンド前後の明示指定を試した
- [ ] セットアップ → クライアント設定表示 → 状態 → 停止 → 起動を通し、各段階の保存済み設定とログイン時の動作を確認した
- [ ] 取消、EOF、不正な入力、再試行、再セットアップ、既存設定、アドレス検出不可、一部失敗、復旧を試した
- [ ] ポート競合や権限不足で、ネットワーク・システム設定を無言で変更せず、具体的な次の一手を案内することを確認した
- [ ] 狭い端末での出力と、アドレス、パス、鍵、コマンド入力、設定値が翻訳で変わらないことを確認した
- [ ] 秘密鍵が状態、質問、ログ、公開する例、インストール用の配布物へ含まれないことを確認した
- [ ] Go の race テストと vet を実行し、対象 OS の launchd・ビルド・署名・インストール確認と、未実施の実クライアント・旧 macOS 確認を分けて記録した
- [ ] 両言語のコマンド、対象版、リンク、動作、検証結果が、対象ソースまたは公開済み配布物と一致している

運用上の境界は[利用ガイドの安全上の説明](../README.md#ネットワークと安全上の境界)、公開の要件は[リリース手順](RELEASING.md)を参照してください。
